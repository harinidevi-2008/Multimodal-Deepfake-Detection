# Multimodal Deepfake Detection Using Visual, Audio, and Semantic Inconsistencies

Mini project — SSN College of Engineering, IT Dept. Guide: Dr. Anjali T.
Team: Kruthika C D (visual), Varshana M (audio), Harini Devi B (fusion), Napster (semantic).

**Status:** the pipeline below is structurally complete and has been verified with synthetic
fixture data. It has **not yet been trained or evaluated on the real FakeAVCeleb dataset** — do
not read anything in this document as a claim of trained/measured accuracy. See "Training and
evaluation protocol" below for what to run, and check `eval/results.txt` (generated by
`eval/generate_report.py`, not committed until you run it) for actual numbers once you have.

## Pipeline

Video → five parallel evidence streams → cross-attention fusion model → real/fake
classifier, plus a plain-language evidence report.

| Stream    | Path                        | Kind                                    | Output dim |
|-----------|-----------------------------|------------------------------------------|-----------|
| Visual    | `visual/src/`                | Learned (EfficientNet-B0)                | 1280      |
| Audio     | `audio/src/`                 | Learned (Wav2Vec 2.0)                    | 768       |
| Semantic  | `semantic/src/`               | Learned (Whisper base → Sentence-BERT MiniLM) | 384  |
| Blink     | `visual/src/eye_blink/`       | Rule-based (EAR thresholds, no training) | 4         |
| Lip-sync  | `visual/src/lipsync/`         | Rule-based (mouth/audio correlation, no training) | 2 |
| Fusion    | `fusion/`                     | Cross-attention fusion over all five projections | → 2 classes |

**Blink and lip-sync are rule-based signals, not learned probabilities.** They come from fixed,
hand-designed thresholds (an Eye Aspect Ratio cutoff; a mouth-motion/audio-energy correlation
cutoff) with no trainable weights and no train/val/test split of their own. Nothing in this
repository should ever call them "probabilities" — the evidence layer calls them
`blink_anomaly_score` and `lip_sync_mismatch_score` specifically to keep that distinction visible.
Visual, audio, and semantic each additionally have their own separately trainable classifier head
(`classifiers/`), independent of the fusion model, so each stream can report its own
`*_fake_probability`.

Each learned stream saves raw, un-projected features to disk as `.npy`. The 384→256 / 768→256 /
1280→256 projections happen **inside the fusion models** (`fusion/fusion_model.py`,
`fusion/enhanced_fusion_model.py`), not in the individual stream scripts — keep it that way; don't
pre-project features before saving.

### Two fusion models, both still supported

- **`fusion/fusion_model.py` (`FusionModel`)** — the original 3-modal baseline (visual + audio +
  semantic). Three modality tokens, cross-attention, fusion, classifier. Preserved as-is.
- **`fusion/enhanced_fusion_model.py` (`EnhancedFusionModel`)** — the current 5-modal model
  (visual + audio + semantic + blink + lip-sync). Five modality tokens projected into the same
  shared 256-d space and attended over jointly (`(B, 5, 5)` attention), not concatenated at the
  end. This is a separate class in a separate file — `FusionModel` was never modified to add this.

Both models, and both training/evaluation scripts, are still present and independently runnable.

## Repo layout

```
visual/src/           frame extraction, face alignment, EfficientNet feature extraction
visual/src/eye_blink/ landmark-based blink detection and irregularity scoring (rule-based)
visual/src/lipsync/   mouth-motion vs audio-energy consistency scoring (rule-based)
audio/src/            audio extraction, mel-spectrogram, Wav2Vec2 feature extraction
semantic/src/         transcription (Whisper) + embedding (Sentence-BERT) + precompute pipeline
classifiers/          per-modality MLP classifier heads (visual/audio/semantic), trained independently

                       shared train/validation/test split, normalization, the descriptive attention
                       summary and ablation-based modality-contribution helpers, feature-quality audit
evidence/              evidence_builder (plain-language reasons), frame_evidence (frame selection)
inference/             application-facing orchestration that ties the above into one result
eval/                  full-suite orchestrator + consolidated results.json/results.txt report

```

### Eye-blink and lip-sync modules

Both are lightweight, rule-based (no trainable weights) and independent of the EfficientNet visual
pipeline and the Wav2Vec2 audio pipeline — neither imports from nor modifies the existing feature
extraction code.

Run them directly:

```bash
python visual/src/eye_blink/eye_blink_manual.py path/to/video.mp4
python visual/src/lipsync/lipsync_manual.py path/to/video.mp4
```

- **Eye-blink**: face-mesh landmarks (MediaPipe) → Eye Aspect Ratio per frame → blink events →
  blink count, rate, and an irregularity score (0-1, higher = more abnormal), fixed threshold 0.5
  for the "Abnormal" status. Samples the video at its own higher frame rate rather than reusing
  the main pipeline's low `DEFAULT_FPS_TARGET`, since individual blinks (100-400ms) would fall
  between sparsely-sampled frames.
- **Lip-sync**: mouth-opening ratio per frame (same landmark model) correlated against the
  audio's RMS energy envelope, with a small search over time-lag to tolerate minor start-offset
  misalignment. Outputs a consistency score (0-1, higher = better synced) and its complement
  `mismatch_score = 1 - consistency`; `lipsync_status_from_consistency()` is the single function
  that decides "Consistent" vs "Inconsistent" (consistency ≥ 0.40) — every other script that needs
  this boundary (evaluation, inference) calls that same function rather than re-deriving an
  equivalent threshold in mismatch-score space, which previously caused a boundary
  off-by-one (see `fusion/test_lipsync_consistency_boundary.py`). Optionally pass
  `compute_windows=True` to `analyze_lipsync()` for best-effort per-window temporal evidence.
  Pass an already-extracted wav via `--audio path.wav`, or let it auto-extract one with ffmpeg.

Both feed into the 5-modal fusion model as precomputed per-video feature vectors (see
"Blink and lip-sync feature precomputation" below) — they are fully wired in, not a future step.

### Individual modality classifiers

`classifiers/` holds a small MLP head trained per-modality on the existing frozen features —
visual (1280-d), audio (768-d), or semantic (384-d) — so each stream can report its own
fake-probability independently of the fusion model. One generic script handles all three
modalities via CLI flags:

```bash
python classifiers/train_classifier.py --modality visual \
    --feature-root visual/data/features_aligned --input-dim 1280

python classifiers/evaluate_classifier.py --modality visual \
    --feature-root visual/data/features_aligned --input-dim 1280 \
    --weights classifiers/best_visual_classifier.pt --split test --save-probs classifiers/visual_probs.npy
```

Training uses the same persistent `fusion/data_split.json` as the fusion models (train-only
training, validation-only checkpointing/early-stopping on F1, test never touched), class-weighted
loss, and writes a per-epoch history to `classifiers/<modality>_training_history.json`.
Evaluation defaults to `--split test` and reports accuracy, precision, recall, F1, ROC-AUC, and a
confusion matrix on that held-out split; `--save-probs` writes per-sample fake-probabilities to
`.npy` for later use by the evidence layer.

**Note:** no trained weights (`best_visual_classifier.pt` etc.) are included in this repo —
training requires the real precomputed `.npy` features, which only exist on the machine that ran
the feature-extraction pipelines. Run `train_classifier.py` yourself once you have those features
in place.

### Blink and lip-sync feature precomputation

Before the fusion model can use blink/lip-sync evidence, those scores need to exist as `.npy`
files mirroring the dataset structure, same as the other three streams.
`visual/src/blink_lipsync_precompute.py` runs `analyze_blinks()` and `analyze_lipsync()` across
every video in a dataset folder and saves two small feature vectors per video:

```bash
python visual/src/blink_lipsync_precompute.py \
    --dataset-root FakeAVCeleb_v1.2 \
    --blink-output visual/data/blink_features \
    --lipsync-output visual/data/lipsync_features
```

Blink vector (4-d): `[blink_count, blink_rate_per_min, average_blink_duration_sec, blink_irregularity_score]`
Lip-sync vector (2-d): `[sync_score, mismatch_score]`

Safe to re-run after an interruption — already-processed videos are skipped.

## Training and evaluation protocol

### 1. The shared split is the single source of truth

`fusion/create_split.py` builds one reproducible, **group-aware** train/validation/test split and
saves it to `fusion/data_split.json` (seed 42, ~70/15/15 by sample count — approximate, not exact,
because identity groups have different sizes). "Group-aware" means every `id<digits>` token found
anywhere in a sample's path (folder or filename — fake clips embed a *second* identity via the
swapped face/voice source) is unioned into one group, and whole groups are assigned to a split
together, so the same identity never appears in two splits.

```bash
python fusion/create_split.py \
    --visual-root visual/data/features_aligned --audio-root audio/data/features \
    --semantic-root semantic/data/features --blink-root visual/data/blink_features \
    --lipsync-root visual/data/lipsync_features
```

After creating it, `create_split.py` (and `--verify-only` against an existing one) checks: no
sample in more than one split; no identity group spanning multiple splits; every split contains
**both** real and fake samples (a split with only one class fails loudly rather than silently
producing meaningless metrics); and every sample still exists under all five feature roots.

**Every training script below trains ONLY on `split_name="train"`, selects/checkpoints ONLY on
`split_name="validation"`, and never touches `test`.** Every evaluation script defaults to
`--split test`. `--split all` is available on every evaluation script strictly for debugging and
is explicitly **not** a valid held-out metric.

### 2. Feature normalization (blink/lip-sync only)

```bash
python fusion/feature_normalization.py \
    --blink-root visual/data/blink_features --lipsync-root visual/data/lipsync_features
```

Fits mean/std on the **train split only**, saves `fusion/feature_normalization.json`, and is
applied identically at train, evaluation, and inference time. Visual/audio/semantic embeddings are
*not* normalized this way — they already pass through a Linear→LayerNorm projection inside the
fusion models. Blink/lip-sync mix incompatible units (a count, a rate, a duration, 0-1 scores) in
one short vector with no such projection of their own, which is why they're the normalization
candidates.

### 3. Training

```bash
# Per-modality classifiers
python classifiers/train_classifier.py --modality visual --feature-root visual/data/features_aligned --input-dim 1280
python classifiers/train_classifier.py --modality audio --feature-root audio/data/features --input-dim 768
python classifiers/train_classifier.py --modality semantic --feature-root semantic/data/features --input-dim 384

# 3-modal baseline
python fusion/train_fusion.py

# 5-modal fusion model
python fusion/train_enhanced_fusion.py
```

All five trainers share the same shape: `--epochs` (a generous max), `--patience` (early stopping
on validation F1, default 5), class-weighted `CrossEntropyLoss`, best-checkpoint-by-validation-F1
(the very first completed validation epoch always establishes a checkpoint, even if it happens to
score exactly F1=0.0 — the best-F1 tracker starts below zero specifically so that edge case can't
silently finish a training run with no checkpoint saved at all), and a JSON training history
(`classifiers/<modality>_training_history.json`, `fusion/fusion_training_history.json`,
`fusion/training_history.json`). All three also refuse to start if either the `train` or
`validation` split turns out to contain only one class — the shared split generator's own checks
should normally prevent that, but a training script should still fail safely against an old,
hand-edited, or otherwise invalid split JSON rather than train (or "select a best model") against
degenerate data. The `test` split is never loaded by any trainer.

**Official protocol for the final 5-modal model:** `train_enhanced_fusion.py` trains correctly
without blink/lip-sync normalization (`--no-normalization`, or simply no normalization file present)
for quick experiments, but prints an explicit `WARNING: training EnhancedFusionModel WITHOUT
blink/lip-sync normalization. This run is experimental and is not the official evaluation protocol.`
in that case, and records `normalization_applied` / `normalization_path` in its training history.
**The final, reported 5-modal model must be trained with train-only normalization** (step 2 above,
run once, then passed via `--normalization-path` to both training and evaluation).

**On the existing `fusion/best_fusion_model.pt`:** that checkpoint predates the shared split
(it was trained with its own random `train_test_split`). It is not deleted or silently
overwritten by this documentation — but for a 3-modal number that is genuinely comparable to the
5-modal model under the same held-out `test` split, re-run `train_fusion.py` to produce a new
checkpoint under the shared protocol.

### 4. Feature-quality audit — hard pre-training gate

```bash
python fusion/audit_features.py
```

Read-only inspection of all five feature roots: file count, shape, dtype, NaN/Inf counts, and
label counts per stream, plus a specific check on the semantic stream's zero-vectors (written
intentionally by `semantic/precompute.py` when a transcript is unreliable) broken down by
Real vs. Fake — flagged if that rate differs sharply by label, since that would mean the semantic
stream could partly be learning "was transcription reliable" rather than "is this fake". Doesn't
change or repair anything automatically — a malformed shape such as `(1, 1280)` is reported, never
silently reshaped.

This is a **hard gate, not just a report**: the script prints a final `FEATURE AUDIT: PASS` or
`FEATURE AUDIT: FAIL` line and exits non-zero on failure. It fails specifically on unreadable
`.npy` files, NaN values, Inf values, or an unexpected feature shape/dimension on any stream —
these would otherwise surface hours into a training run as a NaN loss or a crash. It does **not**
fail merely because zero vectors exist in the semantic stream, or because their Real/Fake rate is
imbalanced — both remain a printed flag for investigation, since zero-vectoring unreliable
transcripts is intentional behavior, not corruption. Treat a `FEATURE AUDIT: FAIL` as a hard stop
before spending time on a real training run.

### 5. Evaluation

```bash
python eval/run_full_evaluation.py       # orchestrates every evaluate_*.py, prints one report
python eval/generate_report.py           # writes eval/results.json + eval/results.txt
```

`eval/generate_report.py`'s report distinguishes four categories: **A** learned single-stream
classifiers, **B** 3-modal learned fusion, **C** 5-modal learned fusion, **D** rule-based
behavioral signals (blink, lip-sync — reported with their own fixed threshold, never as a
"probability"). Every learned-model row reports accuracy/precision/recall/F1/ROC-AUC/confusion
matrix/sample counts/split used; every rule-based row reports the same metrics plus its threshold,
clearly labeled rule-based.

### Evidence and application-facing inference

`evidence/evidence_builder.py` composes the classifier probabilities, the blink/lip-sync results,
and the fusion model's final probability into one structured report with plain-language reasons.
If no individual stream crosses its own threshold, the report says the final result is based on
combined multimodal evidence — it does **not** call that "low confidence" by itself; "low
confidence" is reserved for when `final_fake_probability` itself is genuinely close to the 0.5
decision boundary. `evidence/frame_evidence.py` selects representative frames
(`frame_selection_reason`: `eye_blink_event` from real detected blink timing, or `uniform_sample`)
and keeps that strictly separate from `detected_artifact` (always `None` — there is no visual
artifact detector in this repository; the field exists as a schema slot for one, not as an
implicit claim).

`inference/full_pipeline.py` is the one call that ties everything above together for a single
sample already present in all five feature roots — see its module docstring for the full output
schema. It fails clearly and immediately (`require_file()`, a descriptive `MissingCheckpointError`)
if any of the four required checkpoints (three classifiers + the 5-modal fusion model) hasn't been
trained yet, rather than an obscure `torch.load` error later, and it never silently substitutes
random weights or falls back to the 3-modal checkpoint for a missing 5-modal one.

What you get depends on whether a raw `video_path` is supplied, and the output says so explicitly
via an `evidence_availability` field (`numeric_stream_scores`, `frame_evidence`,
`blink_event_frames`, `lip_sync_window_evidence`, `visual_artifact_detection` — booleans reflecting
what actually ran, not what's aspirational):
- **Precomputed features only** (no `video_path`): every numeric score, the evidence report, and
  attention/contribution are computed as before. `frame_evidence` is `None` and `window_evidence`
  is an explicit "not available" note — neither is fabricated from the single precomputed 2-d
  lip-sync vector.
- **With `video_path` supplied**: `frame_evidence.py`'s frame selection uses genuine blink-event
  timing obtained automatically by reusing `blink_analyzer.py`'s own `compute_ear_series()` +
  `detect_blinks()` (not a reimplementation; falls back to uniform sampling if detection fails or
  finds nothing), and `window_evidence` is computed for real via
  `lipsync_analyzer.analyze_lipsync(video_path, compute_windows=True)` on that same video.
- **`visual_artifact_detection` is always `False`.** There is no visual-artifact detector in this
  repository. A frame selected because it contains a blink event is never described as a "deepfake
  frame" or "proof of forgery" — `frame_selection_reason` (why a frame was picked) stays strictly
  separate from `detected_artifact` (always `None`, a schema slot for a detector that doesn't exist
  yet).

`fusion/attention_utils.py`'s attention summary is **descriptive, not causal** — it says where the
model's attention went, not what caused the prediction. `fusion/modality_contribution.py`'s
ablation-based contribution (zero one modality, measure the shift in P(fake)) is the preferred,
though still heuristic, way to ask which modality mattered.

### What's still open

- **End-to-end raw-video feature extraction** — running the full extraction pipeline
  (visual/audio/semantic feature extraction) on a brand-new video file, rather than one already
  present in the precomputed feature roots, is a separate later phase and is not implemented here.
  (Blink/lip-sync frame- and window-level evidence *can* already be computed directly from a raw
  video via `inference/full_pipeline.py`'s `video_path` argument — see above — that's narrower than
  full feature-extraction-from-scratch.)
- **Visual artifact detection is not implemented.** Nothing in this repository inspects a frame's
  pixels for manipulation artifacts. `detected_artifact` in the evidence/frame schema is always
  `None`, and `evidence_availability.visual_artifact_detection` is always `False` — both are schema
  slots for a real detector that does not exist yet, not implicit claims.
- **External dataset evaluation (DFDC, FaceForensics++)** — deliberately not started. DFDC in
  particular is a **future external generalization-testing dataset** and must not be mixed into
  the FakeAVCeleb training/validation/test split above. It's a separate stage once the backend
  above is validated on FakeAVCeleb.
- **UI integration** — not built here; `inference/full_pipeline.py`'s output schema (including
  `evidence_availability`) is the intended contract for a future UI to consume.
- **The system is not yet trained.** Every checkpoint referenced above is produced by running the
  corresponding training script on real data; none of the numbers in this README are real model
  accuracy, and none should be treated as such until the real FakeAVCeleb training run in
  "Training and evaluation protocol" has actually been performed.

## Checkpoint policy (`.gitignore`)

```
*.pt
!fusion/best_fusion_model.pt
```

Trained checkpoints (`.pt`) are large, machine/run-specific artifacts and are **not** committed by
default — every `best_*.pt` produced by the training scripts above stays local unless explicitly
un-ignored. `fusion/best_fusion_model.pt` is the one deliberate exception: the original 3-modal
baseline checkpoint, kept in the repo as a known-good reference point. If a future checkpoint
should also be committed (e.g. the final selected 5-modal model once real training is complete),
add its exact path as another `!`-exception the same way, rather than removing the blanket `*.pt`
rule — don't commit experimental/intermediate checkpoints by relaxing the rule generally.

Also excluded: generated feature `.npy` files, `features/`/`FakeAVCeleb_v1.2/`/`datasets/`
directories, `*.wav`/`temp_audio/`, `missing_videos.txt`, and any `evidence_frames/` output
directory from `evidence/frame_evidence.py`.

## Running each stream

Each stream expects the dataset (e.g. `FakeAVCeleb_v1.2/`) placed next to that stream's folder, or
update the path constant at the top of the relevant script/config — or, for the fusion/evaluation/
inference scripts listed above, set the corresponding `DFD_*` environment variable
(`fusion/env_defaults.py`) instead of editing source files:

- Visual: `visual/src/config.py` → `VIDEO_FOLDER`
- Audio: `audio/src/config.py`
- Semantic: `semantic/src/precompute.py` → `DATASET_PATH` (auto-detects a few common locations,
  edit directly if your dataset lives elsewhere)

Feature `.npy` files are **not** committed to this repo — they're regenerated locally per machine
(21k+ files, too large for git). Each stream mirrors the dataset's folder structure inside its own
`features/` directory so the fusion datasets can align samples by relative path.

## Known environment gotcha

`transformers==5.x` breaks on `torch==2.2.2`. Stick to `transformers==4.38.2` +
`sentence-transformers==2.7.0`. If you `pip freeze` after installing something new and it bumps
these versions, do not commit that requirements.txt without testing all three learned streams
first.
